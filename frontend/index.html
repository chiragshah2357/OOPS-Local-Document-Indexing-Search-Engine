A search engine for a folder of text files.

It reads each .txt file once, builds an index of every word, and ranks the files that contain your words by how many times those words appear.

    How it works

    Indexing happens once. After that, each search is a few lookups in the index. The examples use one of the sample files.

    1. Read

      Walks the folder and loads every .txt file into a string.

      threads-and-synchronization.txt

      A thread is the smallest unit of execution in Java.

    2. Split

      Lowercases the text, breaks it into words and drops common words such as "the" and "is".

      a thread is the smallest unit of execution in java

    3. Index

      Records which files contain each word, and how many times it appears in each.

      thread
      threads-and-synchronization.txt2
      java
      file-io-basics.txt2
      java-collections.txt2
      exception-handling.txt1
      threads-and-synchronization.txt1

    4. Rank

      Looks up each query word, combines the file sets, and sorts by total hits.

    Where the course topics are used

    The Java classes and collections from the syllabus, and what each one does in this project.

    HashMap

    The inverted index. Each word maps to the files containing it, with a count per file.

    HashMap<String, Map<Integer, Integer>> index

    HashSet

    Holds the stop words. All words is a set intersection and any word is a union, done by two subclasses of the abstract Matcher class.

    PriorityQueue

    Returns the results best first. SearchResult implements Comparable: higher score first, then file name.

    File I/O and Strings

    Walks the folder with recursion, reads each file with a BufferedReader and cuts the text into lowercase words.

    LinkedList

    Keeps the last ten searches, newest first. When it is full, the oldest search is removed from the end.
